## 밀릴 때 자르는 순서

1. 모델 비교 실험 (Opus vs Haiku)
2. 담당자 추천 (F4)
3. 중복 탐지 (F3)

11/27 최소 시연 버전은 절대 자르지 않는다. F1 + F2 + F5만으로도 발표와 보고서가 성립한다.

## 운영 규칙

1. 매일 끝에 `experiment_log.md`에 한 줄 이상 기록
2. 한 번에 하나만 바꾸고 평가 실행
3. 그날 완료 정의를 못 채우면 다음 날로 넘기되, 위 순서대로 뒤쪽 기능을 줄인다
4. Actions에 올리기 전에 로컬에서 `make dry ISSUE=N`으로 먼저 확인
