# 06. 보안 설계

작성일: 2026-11-24

## 1. 전제

이슈 제목과 본문은 저장소 외부의 누구나 쓸 수 있다. IssuePilot은 이 글을 LLM에 넣고, 그 결과로 저장소에 라벨과 코멘트를 쓴다. 따라서 "이슈 작성자가 봇을 조종해 저장소에 원하는 것을 쓰게 만드는 것"이 핵심 위협이다.

## 2. 위협과 대응

| # | 위협 | 대응 | 위치 | 검증 |
|---|---|---|---|---|
| T1 | 프롬프트 주입으로 분류 조작 ("P0으로 분류하라") | 시스템 프롬프트에 입력은 데이터라는 규칙 명시. 구획 태그 위조 무력화 | `prompts/system.md`, `domain/text.for_prompt` | `test_injection_live.py` 2건 (실제 API) |
| T2 | LLM 출력을 통해 임의 라벨 부착 | 저장소에 존재하는 영역 라벨만 통과 | `domain/policy.normalize` | `test_policy.py`, `test_triage.py` |
| T3 | 코멘트에 피싱 링크·임의 사용자 멘션·HTML 삽입 | 자유 서술 문장에서 URL·링크·HTML 제거, `@` 무력화, 줄바꿈·표 구분자 제거, 길이 제한 | `domain/text.for_comment` | `test_text.py`, `test_comment.py` |
| T4 | 지어낸 이슈 번호로 중복 표시 | 검색 어댑터가 돌려준 번호만 허용 | `domain/policy.normalize` | `test_policy.py` |
| T5 | 워크플로 스크립트 주입 (제목에 셸 구문) | 이슈 내용은 워크플로 식에 넣지 않음. 번호만 환경 변수로 전달하고 ASCII 숫자인지 검증 | `deploy/issue-pilot.yml`, `cli.parse_issue_number` | `test_cli_and_log.py` |
| T6 | 과도한 권한의 토큰 | 워크플로 기본 권한 없음. job에 `contents: read`, `issues: write`만. 체크아웃 자격 증명 미보존 | `deploy/issue-pilot.yml` | 설정 검토 |
| T7 | 공급망: 액션 태그 변조, 의존성 변경 | 액션을 커밋 SHA로 고정. 실행 의존성 버전 고정. Dependabot 주간 점검 | 워크플로, `requirements-run.txt`, `dependabot.yml` | 설정 검토 |
| T8 | 비용 소진 (거대한 본문, 대량 이슈) | 제목 300자·본문 8,000자 상한, 출력 토큰 상한, 재시도 2회, job 5분 제한, 이슈별 동시 실행 1개, 봇 작성 이슈 무시 | `config.Settings`, 워크플로 | `test_anthropic_classifier.py` |
| T9 | API 키 유출 | `.env`는 git 제외. Actions에서는 Secrets. 배포 스크립트가 키 형태 문자열을 발견하면 중단. 로그·코멘트에 예외 메시지 원문을 쓰지 않음 | `.gitignore`, `deploy_to_testbed.sh`, `triage.py` | `test_triage.py` |
| T10 | 소스코드 외부 전송 | LLM에는 이슈 텍스트, 라벨 이름, 폴더 이름만 전송. 파일 내용은 보내지 않음 | `anthropic_classifier.build_*` | 코드 검토 |
| T12 | 기존 이슈 본문을 통한 간접 주입 (유사 이슈로 검색되어 프롬프트에 들어감) | 유사 이슈 제목·본문도 새 이슈와 같은 정화(구획 태그 무력화)와 길이 제한(500자)을 거침. 시스템 프롬프트가 `<similar_issues>`도 데이터로 규정 | `anthropic_classifier.build_issue_block` | `test_anthropic_classifier.py` |
| T13 | 임베딩 모델 공급망 (실행 중 외부에서 모델 내려받기) | fastembed 버전 고정, 모델은 러너 캐시에 보관. 모델은 ONNX 추론만 하고 결과는 후보 선정에만 쓰이며 최종 판정·게시 내용은 기존 검증을 그대로 거침 | `requirements-run.txt`, 워크플로 | 설정 검토 |
| T14 | 담당자 추천에 임의 문자열 노출 (git 작성자 이름은 누구나 지정 가능) | 이름을 코멘트용으로 정화하고 코드 서식 안에 표시. 멘션하지 않고 지정하지 않음. 봇 계정 제외 | `domain/comment`, `domain/assignment` | `test_comment.py`, `test_assignment.py` |
| T15 | 액션 입력값을 통한 스크립트 주입 | `action.yml`에서 입력값을 셸 명령에 직접 넣지 않고 환경 변수로만 전달. 내부에서 쓰는 액션도 SHA 고정 | `action.yml` | 설정 검토 |
| T16 | 저장소 공개에 따른 개발자 본인의 비용·정보 노출 | 이 저장소에는 API 키 Secret을 두지 않고, 이슈로 실행되는 워크플로도 두지 않음(CI는 시크릿 없이 읽기 권한만). 설치한 사람의 키는 그 사람의 저장소 Secrets에만 있음. 공개 전 이력 전체에서 키·개인 정보 검사 | `.github/workflows/ci.yml` | 2026-11-26 점검 |
| T11 | 재실행으로 코멘트 도배 | 마커가 있는 기존 코멘트를 갱신 | `github_tracker.upsert_comment` | `test_github_tracker.py` |

## 3. 사람 우선 원칙

- 담당자는 추천만 하고 지정하지 않는다.
- 이슈를 닫지 않는다.
- 라벨은 사람이 언제든 바꿀 수 있고, 코멘트에 자동 분석임을 밝힌다.

## 4. 남은 위험 (수용)

| 위험 | 이유 |
|---|---|
| 정교한 주입으로 유형·우선순위 판단이 흔들릴 수 있음 | 완전한 방어는 불가능. 피해 범위가 "저장소에 이미 있는 라벨 하나가 잘못 붙는 것"으로 제한되고 사람이 수정 가능 |
| 임베딩 모델 파일의 해시를 직접 검증하지 않음 | fastembed가 받는 공식 배포본에 의존. 모델이 변조돼도 영향은 "중복 후보 선정이 틀리는 것"으로 제한 |
| 공개 저장소에서 다수 계정이 이슈를 대량 생성하면 비용 발생 | 건당 약 2센트. 필요 시 작성자 권한(author_association) 조건이나 일일 한도 추가 |
| 요약문에 이슈 본문의 민감 정보가 다시 노출될 수 있음 | 원문이 이미 같은 이슈에 공개되어 있어 추가 노출이 아님 |
| Anthropic API로 이슈 텍스트가 전송됨 | 비공개 저장소에서 쓸 때는 조직 정책 확인 필요 |
