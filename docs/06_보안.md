# 06. 보안 설계

작성일: 2026-11-24 · 최종 점검: 2026-11-27 (5절)

## 1. 전제

이슈 제목과 본문은 저장소 외부의 누구나 쓸 수 있다. IssuePilot은 이 글을 LLM에 넣고, 그 결과로 저장소에 라벨과 코멘트를 쓴다. 따라서 "이슈 작성자가 봇을 조종해 저장소에 원하는 것을 쓰게 만드는 것"이 핵심 위협이다.

## 3. 사람 우선 원칙

- 담당자는 추천만 하고 지정하지 않는다.
- 이슈를 닫지 않는다.
- 라벨은 사람이 언제든 바꿀 수 있고, 코멘트에 자동 분석임을 밝힌다.

## 4. 남은 위험 (수용)

| 위험 | 이유 |
|---|---|
| 정교한 주입으로 유형·우선순위 판단이 흔들릴 수 있음 | 완전한 방어는 불가능. 피해 범위가 "저장소에 이미 있는 라벨 하나가 잘못 붙는 것"으로 제한되고 사람이 수정 가능 |
| 임베딩 모델 파일의 해시를 직접 검증하지 않음 | fastembed가 받는 공식 배포본에 의존. 모델이 변조돼도 영향은 "중복 후보 선정이 틀리는 것"으로 제한 |
| 공개 저장소에서 다수 계정이 이슈를 대량 생성하면 비용 발생 | 건당 약 2센트, 최악의 경우(출력 상한 × 재시도 3회)에도 건당 상한이 있음. 필요 시 작성자 권한(author_association) 조건이나 일일 한도 추가 |
| 요약문에 이슈 본문의 민감 정보가 다시 노출될 수 있음 | 원문이 이미 같은 이슈에 공개되어 있어 추가 노출이 아님 |
| 사실처럼 꾸민 거짓 내용("결제가 전부 실패합니다")은 걸러낼 수 없음 | 모델은 이슈 내용의 진위를 확인할 수 없다. 근거 없는 과장은 걸러내지만(5절) 그럴듯한 거짓 보고는 사람의 보고와 구별되지 않음. 라벨은 사람이 수정 |
| 실행 의존성의 하위 의존성은 버전·해시 미고정 | 직접 의존성 5개만 고정. 해시 고정은 플랫폼별 휠 관리 부담이 커 보류 |
| `@v1` 태그는 움직일 수 있음 | 엄격히 고정하려는 사용자는 커밋 SHA로 지정 (README 안내) |
| Anthropic API로 이슈 텍스트가 전송됨 | 비공개 저장소에서 쓸 때는 조직 정책 확인 필요 |

## 5. 공격 점검 기록 (2026-11-27)

실제 모델(claude-opus-5-5, effort low)에 공격 입력 12종을 넣고, 정화 함수에는 우회 문자열 12종을 넣었다.

**모델 대상 (12종 모두 방어)**: base64로 감춘 지시, 저장소 소유자 사칭, 가짜 assistant 응답 삽입, HTML 주석 속 지시, 유니코드 태그 문자로 숨긴 지시, 전각·공백 변형 구획 태그, 출력 길이 팽창 유도(출력 137토큰으로 평소와 같음), 코멘트에 링크·멘션·HTML 넣기 유도, 시스템 프롬프트 출력 요구, 기존 이슈를 통한 간접 주입, 작성자의 중복 은폐 시도, 근거 없는 영향 부풀리기. 이 가운데 7종은 `test_injection_live.py`에 회귀 테스트로 남겼다.

**정화 함수 대상 (우회 6종 발견, 모두 수정)**: 모델이 속지 않아 실제 피해는 없었지만, 모델이 속았다면 코멘트에 그대로 나갔을 문자열이다.

| 우회 | 원인 | 수정 |
|---|---|---|
| `<a⏎href="//evil">` | 줄바꿈이 든 태그는 지우지 않았고, 이후 공백 정리로 유효한 태그가 됨 | 공백을 먼저 정리한 뒤 태그 제거, 남은 꺾쇠는 엔티티로 |
| 닫히지 않은 `<!--` | 닫는 표시가 있어야만 지움. 코멘트 뒷부분(면책 문구 포함)이 숨겨짐 | 닫히지 않은 주석은 끝까지 제거 |
| 200자를 넘는 태그 | 길이 상한 밖 | 상한 확대 + 엔티티 변환 |
| `&#64;user` | 엔티티로 만든 `@` | `&`를 엔티티로 변환 |
| `owner/repo#1` | 다른 저장소 이슈에 역참조가 남음 | `#숫자` 무력화 |
| 방향 전환 문자(U+202E) 등 | 보이지 않는 문자 미처리 | 제어·서식 문자 제거 |

**점검했으나 문제없던 것**: 워크플로 명령 주입(`::` 로 시작하는 줄을 로그에 찍게 하기)은 코멘트의 모든 줄이 고정 문구로 시작해 불가. 이슈 수정으로 재분석 유발은 `opened`에만 반응하므로 불가. 포크 PR을 통한 시크릿 탈취는 `issues` 이벤트가 기본 브랜치 코드만 실행하므로 불가.
