# 03. 평가 계획

작성일: 2026-10-26 | 상태: **확정(v1.0)** | 평가셋은 스프린트 중 수정 금지 (오류 발견 시 "수정 대기" 목록에 적고 스프린트 회고 때 반영)

## 1. 왜 먼저 만드는가

루프를 돌릴 때 "좋아졌다"를 판단하는 유일한 기준. 평가셋이 없으면 프롬프트 수정은 감으로 하게 되고, 최종 보고서에 넣을 숫자도 없다.

## 2. 평가셋 구성 (목표 100건)

| 출처 | 건수 | 용도 | 작성 방법 |
|---|---|---|---|
| 직접 작성 (manual) | 30 | 중복 쌍·누락 정보·담당자 추천처럼 통제된 케이스 | `eval/eval_set.csv`에 시드 30건 포함. 테스트 저장소에 그대로 등록 |
| FastAPI 공개 이슈 | 40 | 실제 분포 반영, 라벨 정확도 | GitHub API로 최근 closed 이슈 수집, 실제 라벨을 정답으로 사용 |
| Streamlit 공개 이슈 | 30 | 도메인 다양성 | 동일 |

**분할:** 개발용(train) 60건 / 검증용(test) 40건. 프롬프트 튜닝은 train만 보고 하고, test는 스프린트 끝에만 측정한다. test 점수가 보고서의 대표 수치.

**직접 작성 30건의 설계 의도**
- 유형별 균형: bug 12, feature 9, question 5, docs 4
- 중복 쌍 5개 포함 (원본 + 다르게 표현한 중복), 비슷해 보이지만 다른 이슈 3쌍 포함(오탐 테스트)
- 버그 12건 중 6건은 재현 방법·환경 등 누락
- 영역이 명확한 이슈 20건, 모호한 이슈 10건
- 한국어 20건, 영어 10건

## 3. 지표 정의

| 지표 | 계산 | 목표 | 대응 기능 |
|---|---|---|---|
| 유형 정확도 | 예측 type == gold_type 비율 | ≥ 80% | F1 |
| 우선순위 정확도 | 예측 priority == gold_priority 비율 | ≥ 70% | F1 |
| 우선순위 인접 정확도 | 한 단계 차이까지 허용 | ≥ 90% | F1 |
| 영역 라벨 F1 | 예측 labels vs gold_labels 집합 F1 (건별 평균) | ≥ 0.70 | F1 |
| 중복 정밀도 | 중복이라 판정한 것 중 실제 중복 비율 | ≥ 90% | F3 |
| 중복 재현율 | 실제 중복 중 잡아낸 비율 | ≥ 70% | F3 |
| 누락 정보 적중률 | 예측 missing_info vs gold 집합 F1 | ≥ 0.80 | F2 |
| 담당자 일치율 | 추천 1순위 == 기대 담당자 (manual 20건) | ≥ 80% | F4 |
| 재현성 | 같은 이슈 3회 분류 유형 일치율 | ≥ 90% | N3 |
| 건당 비용 | (input_tokens·단가 + output_tokens·단가) 평균 | ≤ $0.05 | N2 |
| 건당 지연 | LLM 호출 latency_ms 평균 | ≤ 15초 | N1 |

**정밀도를 재현율보다 높게 잡은 이유:** 중복이 아닌데 중복이라고 하면 사용자가 봇을 불신한다. 놓치는 것보다 틀리게 잡는 것이 더 해롭다.

## 4. 실행 방법

```bash
python eval/run_eval.py --split train            # 개발 중 수시 실행
python eval/run_eval.py --split test             # 스프린트 종료 시
python eval/run_eval.py --split test --repeat 3  # 재현성 측정
```

출력: 콘솔 요약표 + `eval/results/YYYY-MM-DD_HHMM.json` (건별 예측·정답·토큰·지연 저장)

## 5. 비용 예산

- train 60건 1회 ≈ 60 × $0.02 = $1.2 (Opus 5.5 기준)
- 스프린트당 train 10회 + test 2회 ≈ $15
- 전체 4스프린트 ≈ $60
- 실제: 평가셋을 30건으로 줄여 1회 평가(train 20건)에 약 $0.35

## 6. 보고서에 들어갈 표 (미리 정해둠)

1. 스프린트별 test 지표 추이 (표 + 꺾은선)
2. 프롬프트 변경 전후 비교 (experiment_log에서 추출)
3. 모델 비교: Opus 5.5 vs Haiku 5.5 — 정확도·비용·지연
4. 중복 탐지: 임베딩 단독(임계값 0.3~0.8)과 임베딩 + LLM 2단계의 정밀도·재현율 비교 (실험 #2). 처음 계획한 임계값 0.80~0.90은 사용한 모델의 유사도 분포(중복 쌍 0.36~0.75)와 맞지 않아 범위를 바꿈
5. 실패 사례 분석 5건 (왜 틀렸는지)
