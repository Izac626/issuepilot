# 01. 요구사항 명세서

작성일: 2026-10-26 | 상태: **확정(v1.0)** | 변경 시 하단 변경 이력에 기록

## 1. 프로젝트 정의

**한 줄 정의:** GitHub 저장소에 이슈가 등록되면 1분 안에 LLM이 분류·중복 탐지·담당자 추천·보완 요청을 이슈 페이지에 자동으로 남기는 에이전트.

**해결하는 문제:** 이슈 분류·배정은 사람이 ChatGPT에 하나씩 복사해 물어보는 방식으로는 해결되지 않는다. (1) 이슈 등록 시점에 자동으로 실행되어야 하고, (2) 저장소의 기존 이슈·커밋 이력을 참조해야 하며, (3) 기준이 일관되고 근거가 기록되어야 하기 때문이다.

**사용자:** 팀 프로젝트 저장소 관리자, 소규모 개발팀, 오픈소스 메인테이너

## 2. 기능 요구사항

| ID | 기능 | 입력 | 출력 | 완료 조건 | 우선순위 |
|---|---|---|---|---|---|
| F1 | 자동 라벨링·우선순위 | 이슈 제목·본문, 저장소 라벨 목록 | 유형 1개, 영역 라벨 0~3개, 우선순위(P0~P2), 근거 문장 | 평가셋 유형 정확도 ≥ 80%, 우선순위 정확도 ≥ 70% | 필수 |
| F2 | 누락 정보 보완 요청 | 이슈 본문 (유형이 bug인 경우) | 누락 항목 목록(재현 방법/환경/기대 동작/실제 동작), 요청 코멘트 문구 | 평가셋 누락 항목 적중률 ≥ 80% | 필수 |
| F3 | 중복 이슈 탐지 | 새 이슈, 기존 이슈 임베딩 | 중복 후보 이슈 번호 0~3개, 각각 유사도·판정·근거 | 중복 정밀도 ≥ 90%, 재현율 ≥ 70% | 필수 |
| F4 | 담당자 추천 | 영향 영역(파일 경로), 커밋 이력, 열린 이슈 수 | 추천 담당자 1~2명, 추천 근거(커밋 수·현재 부하) | 테스트 저장소에서 기대 담당자와 일치 ≥ 80% | 필수 |
| F5 | 결과 게시 | F1~F4 결과 | 라벨 부착, 분석 코멘트 1개 | 이슈 생성 후 60초 내 반영 | 필수 |
| F6 | 주간 리포트 | 최근 7일 이슈 | 유형 분포, 미처리 P0, 담당자 부하 요약 Discussion | 수동 실행으로 생성 확인 | 선택 |
| F7 | 대시보드 | 분류 로그(SQLite) | 분류 통계, 정확도 추이 Streamlit 화면 | 로컬 실행 확인 | 선택 |

## 3. 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| N1 | 응답 시간 | 이슈 생성 → 코멘트 등록 60초 이내 (Actions 부팅 포함 120초 이내) |
| N2 | 비용 | 이슈 1건당 LLM 비용 0.05달러 이하 |
| N3 | 재현성 | 같은 이슈를 3회 분류했을 때 유형 일치율 ≥ 90% |
| N4 | 출력 형식 | LLM 출력은 항상 Pydantic 스키마 검증 통과. 실패 시 최대 2회 재요청 후 "분류 실패" 코멘트 |
| N5 | 보안 | API 키·토큰은 GitHub Secrets에만 저장. 소스코드 본문은 LLM에 전송하지 않음(파일 경로·폴더 구조만) |
| N6 | 사람 우선 | 담당자는 "추천"만 하고 자동 지정하지 않음. 라벨은 자동 부착하되 사람이 제거 가능 |

## 4. 범위 밖 (하지 않는 것)

- Pull Request 분석·리뷰 (이슈만 다룸)
- 담당자 자동 assign (추천 코멘트까지만)
- 이슈 자동 close (중복 판정이어도 닫지 않음)
- 소스코드 본문을 LLM에 전송하는 기능
- 다국어 UI (코멘트는 한국어 고정, 이슈 본문은 한·영 모두 처리)
- GitHub 이외 플랫폼(GitLab, Jira)

## 5. 제약 조건

- 실행 환경: GitHub Actions (별도 서버 없음)
- LLM: Anthropic API (Claude Opus 5.5)
- 임베딩: 로컬 모델(paraphrase-multilingual-MiniLM-L12-v2, ONNX) — Anthropic 임베딩 API 없음. 처음 계획한 bge-m3는 2GB라 Actions에서 제외 (2026-11-26 변경)
- 개발 기간: 2026-11-24 ~ 2026-12-01 (처음 계획은 3주였으나 1주로 줄임. 04 문서 참고)

## 6. 용어

| 용어 | 정의 |
|---|---|
| 유형(type) | bug / feature / question / docs 중 하나 |
| 영역 라벨 | backend / frontend / auth / db / infra / docs 등 저장소에 존재하는 라벨 |
| 우선순위 | P0(서비스 불가·전체 영향), P1(주요 기능 장애·우회 가능), P2(경미·개선) |
| 중복 | 같은 원인 또는 같은 요청을 다루는 기존 이슈가 있는 경우 |
| 영향 영역 | 이슈가 수정을 요구할 가능성이 높은 파일·폴더 경로 |
