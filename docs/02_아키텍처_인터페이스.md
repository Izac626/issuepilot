# 02. 아키텍처 및 인터페이스 계약 (v2.1, 헥사고날)

개정일: 2026-11-26 | 이전 파이프라인형 설계는 `02_아키텍처_인터페이스_v1(구).md`

## 1. 구조

포트와 어댑터(헥사고날) 구조. 업무 규칙은 안쪽에, GitHub·LLM·파일 같은 외부 기술은 바깥쪽에 둔다.

```
            인바운드 어댑터                      아웃바운드 어댑터
         (누가 시스템을 부르나)                  (시스템이 무엇을 부르나)

  ┌───────────────────┐                        ┌────────────────────────┐
  │ cli.py             │                        │ github_tracker.py      │ GitHub API
  │ (명령행, Actions   │                        ├────────────────────────┤
  │  환경 변수)        │     ┌──────────────┐   │ anthropic_classifier.py│ Claude API
  └─────────┬─────────┘     │  application  │   ├────────────────────────┤
            │               │               │   │ jsonl_log.py           │ 파일
            ▼               │  TriageIssue  │   ├────────────────────────┤
     bootstrap.py ────────▶ │  (유스케이스) │──▶│ fastembed_embedder.py  │ 로컬 임베딩 모델
     (조립 지점)            │  유사 검색    │   ├────────────────────────┤
                            │  담당자 추천  │   │ github_history.py      │ GitHub 커밋 API
                            │   ports.py    │   └────────────────────────┘
                            └──────┬───────┘          ▲ 포트를 구현
                                   ▼                  │
                            ┌──────────────┐          │
                            │    domain     │──────────┘
                            │ models policy │
                            │ comment text  │
                            │ assignment    │
                            └──────────────┘
```

## 2. 계층과 의존 규칙

| 계층 | 경로 | 내용 | import 가능 대상 |
|---|---|---|---|
| domain | `issuepilot/domain/` | 모델, 분류 결과 정규화 규칙, 코멘트 본문 생성, 텍스트 정화 | 표준 라이브러리, pydantic |
| application | `issuepilot/application/` | 포트(Protocol) 정의, `TriageIssue` 유스케이스 | domain |
| adapters | `issuepilot/adapters/inbound|outbound/` | 포트 구현, 외부 기술 연동 | application, domain, config |
| bootstrap | `issuepilot/bootstrap.py` | 어댑터를 골라 유스케이스에 꽂는 유일한 곳 | 전부 |

규칙은 `tests/test_architecture.py`가 import 구문을 분석해 강제한다. 위반하면 CI가 실패한다.

## 3. 포트 (`application/ports.py`)

| 포트 | 메서드 | 현재 구현 | 필수 |
|---|---|---|---|
| `IssueTracker` | `fetch`, `add_labels`, `upsert_comment` | `GitHubIssueTracker` | 필수 |
| `IssueClassifier` | `classify → (RawClassification, ClassifierUsage)` | `AnthropicClassifier` | 필수 |
| `SimilarIssueFinder` | `find_similar → list[SimilarIssue]` | `EmbeddingSimilarityFinder` (application) | 선택 |
| └ `IssueCatalog` | `list_existing → list[ExistingIssue]` | `GitHubIssueTracker` | |
| └ `Embedder` | `embed(texts) → 벡터 목록` | `FastEmbedEmbedder` | |
| `AssigneeRecommender` | `recommend → AssigneeRecommendation` | `HistoryAssigneeRecommender` (application) | 선택 |
| └ `ContributionHistory` | `commit_counts(path)`, `open_issue_counts()` | `GitHubContributionHistory` | |
| `ResultLog` | `append(PilotResult)` | `JsonlResultLog` | 선택 |

유사 검색과 담당자 추천은 계산 절차(코사인 유사도, 순위 규칙)가 업무 규칙이라 application·domain에 두고, 외부 기술이 필요한 부분만 하위 포트(└)로 뺐다. 임베딩 모델이나 이력 출처를 바꿀 때는 하위 포트의 어댑터만 교체한다.

선택 포트는 `None`이면 해당 단계를 건너뛴다. 실행 중 예외가 나도 경고만 남기고 분류 결과는 게시한다(부가 기능이 핵심 기능을 막지 않는다). 기능을 추가할 때는 어댑터를 만들고 `bootstrap.py`에 한 줄을 넣으며, 유스케이스와 도메인은 건드리지 않는다.

## 4. 유스케이스 흐름 (`TriageIssue.run`)

1. `tracker.fetch` → 이슈와 저장소 컨텍스트
2. `finder.find_similar` → 유사 이슈 후보 최대 3건. 번호가 앞선 이슈 최근 100건을 임베딩해 코사인 유사도 0.30 이상만 (4.1 참고)
3. `classifier.classify` → 원본 판단. 실패하면 실패 코멘트를 달고 종료
4. `domain.policy.normalize` → 허용된 라벨·폴더·이슈 번호만 남김
5. `recommender.recommend` → 담당자 후보 최대 2명 (4.2 참고)
6. `domain.comment.render_comment`, `policy.labels_to_apply`
7. `tracker.add_labels`, `tracker.upsert_comment` (dry-run이면 생략)
8. `result_log.append`

### 4.1 중복 탐지 (2단계)

1. **검색**: 새 이슈와 기존 이슈의 `제목 + 본문 앞 1,000자`를 로컬 임베딩 모델(paraphrase-multilingual-MiniLM-L12-v2, 384차원, ONNX)로 벡터화하고 코사인 유사도 상위 3건을 고른다. 이슈 내용은 임베딩 단계에서 외부로 나가지 않는다.
2. **판정**: 후보의 제목과 본문 앞 500자를 분류 프롬프트에 함께 넣고, LLM이 후보마다 중복 여부와 이유를 낸다. 분류와 같은 호출이라 API 호출 수는 늘지 않는다.

임베딩만으로 판정하지 않는 이유: 평가셋에서 중복 쌍의 유사도(0.36~0.75)와 중복이 아닌 쌍의 유사도(최고 0.70)가 겹쳐, 어떤 임계값으로도 정밀도 90%와 재현율 70%를 동시에 만족하지 못했다(실험 #2). 그래서 임계값은 재현율 위주로 낮게(0.30) 잡고 정밀도는 LLM이 책임진다.

벡터 저장소(ChromaDB)를 두지 않은 이유: 실행 환경이 일회성 Actions 러너라 저장소를 유지하려면 별도 동기화가 필요하다. 최근 100건을 매번 임베딩해도 1초 미만이라 상태를 두지 않는 쪽이 단순하고 항상 최신이다. 이슈가 수천 건인 저장소로 넓힐 때 `Embedder` 뒤에 캐시나 벡터 저장소 어댑터를 추가한다.

### 4.2 담당자 추천

영향 폴더별 최근 커밋 100건의 작성자를 세고(`ContributionHistory`), `domain/assignment.py`가 점수를 매긴다.

`점수 = (1순위 폴더 커밋 수 + 0.5 × 나머지 폴더 커밋 수) ÷ (1 + 0.2 × 열린 담당 이슈 수)`

봇 계정은 제외하고 상위 2명을 추천한다. 지정은 하지 않는다.

## 5. 신뢰 경계

LLM의 출력은 신뢰하지 않는다. 어댑터는 원본 판단(`RawClassification`)만 돌려주고, 무엇을 게시할지는 도메인이 결정한다.
- 라벨: 저장소에 실제로 있는 영역 라벨만
- 폴더: 저장소에 실제로 있는 폴더만
- 중복 이슈 번호: 검색 어댑터가 찾아 준 번호만
- 자유 서술 문장: 멘션·링크·HTML 제거 후 게시

자세한 위협과 대응은 `06_보안.md`.

## 6. LLM 호출 계약 (`AnthropicClassifier`)

- 모델 `claude-opus-5-5`, effort `low` (환경 변수 `PILOT_MODEL`, `PILOT_EFFORT`로 교체)
- `messages.parse`에 `RawClassification`을 출력 형식으로 지정
- 입력 순서: 시스템 프롬프트(고정) → 저장소 컨텍스트 → 유사 이슈 → 새 이슈
- 형식 위반·출력 잘림은 최대 2회 재요청, 거절(refusal)은 재요청하지 않음
- 프롬프트는 `adapters/outbound/prompts/system.md` (코드와 분리해 버전 추적)
